# Local Lucy V11 — Gemma/Llama Request-Parity Repair Report

**Branch:** `v11-routing-parity-2026-07-25`  
**Date:** 2026-07-25  
**Status:** complete — all regression tests pass

## 1. Root cause(s)

1. **Keyword-to-URL conversion in the trusted-source fetch path.**  
   `tools/unverified_context_trusted.py` built fetch candidates by appending arbitrary non-stop words from the user query to trusted domains, e.g.:
   - `https://medlineplus.gov/internal.html`
   - `https://medlineplus.gov/consistency.html`
   - `https://medlineplus.gov/tools.html`
   These invented URLs were then fetched, producing repeated HTTP 404s.

2. **Broad substring medical-keyword matching.**  
   `tools/router_py/policy.py` used `if keyword in normalized`, so short medical tokens matched inside unrelated words:
   - `cut` matched `execution`
   - `flu` matched `influence`
   - `operation` matched `operational`
   This caused the reference self-model prompt to be classified as `medical_context`.

3. **No deterministic enforcement of explicit user restrictions before routing.**  
   Phrases such as "Do not use network access" were not translated into request-scoped capability constraints until after route selection and evidence planning, so a model-generated plan could still issue HTTP fetches.

4. **Unsafe fallback messaging.**  
   When trusted evidence failed, the execution engine returned a generic medical/veterinary/legal disclaimer, which turned a software-consistency failure into an apparent medical evidence failure.

## 2. Earliest divergence point

The two models received the same assembled Ollama prompt (same system injection, memory, persona fragment, and user text).  
Divergence happened at **route classification / evidence planning**:
- The classifier tagged the reference prompt as `medical_context` because of substring keyword hits.
- Gemma’s output path happened to hit the existing `explicit_assistant_instruction` policy gate, forcing `LOCAL`.
- Llama’s path continued into `EVIDENCE`, where `unverified_context_trusted.py` turned individual prompt words into MedlinePlus URLs.

## 3. Whether the models originally received equivalent assembled requests

Yes, at the Ollama level the requests were equivalent: the same user message, the same self-knowledge/persona/context blocks, the same model options (size/temperature/top-p are model-specific via Modelfile), and the same chat-template delegation to Ollama.  
The non-equivalence was in **routing and capability enforcement**, not in prompt assembly.

## 4. Raw malformed planner behaviour that produced MedlinePlus paths

`unverified_context_trusted.py` stripped stop words from the query and produced candidates such as:

```
https://medlineplus.gov/internal.html
https://medlineplus.gov/consistency.html
https://medlineplus.gov/exercise.html
https://medlineplus.gov/information.html
https://medlineplus.gov/tools.html
https://medlineplus.gov/network.html
https://medlineplus.gov/access.html
https://medlineplus.gov/files.html
https://medlineplus.gov/memory.html
```

These were generated by the deterministic candidate builder, not by an LLM planner, and were tagged `URLProvenance.INVENTED_KEYWORD` after the fix.

## 5. Why the explicit no-network instruction was ignored

There was no pre-routing control layer.  The restriction was only present in natural language inside the prompt, so model compliance was the security boundary.  Llama did not voluntarily honour it, and the evidence fetcher had no typed capability denial to check before issuing HTTP requests.

## 7. Exact behavioural changes

### Request-scoped capability constraints
- `extract_request_constraints()` parses explicit denials (network, tools, files, memory writes, local-only) before any routing.
- `main.execute_plan_python()` always extracts or accepts caller-supplied constraints and passes them into the pipeline.
- `request_pipeline.process()` degrades `EVIDENCE/AUGMENTED/NEWS/FULL` to `LOCAL` when `network=False`, and `TIME/WEATHER/FINANCE` to `LOCAL` when `tools=False`, instead of returning a generic denial.
- `_persist_memory_turn()` skips SQLite/text persistence when `memory_write=False`.

### Typed separation of search queries and fetchable URLs
- `SearchQuery` and `FetchURL` dataclasses in `url_provenance.py`.
- `validate_fetch_url()` rejects non-string input, non-HTTPS schemes, missing hostnames, and `INVENTED_KEYWORD` provenance.

### Planner-output validation
- `PlannerValidator` rejects prose, malformed JSON, unknown fields, single-word queries, and fabricated root-level URLs.

### Trusted-source fetch hardening
- `unverified_context_trusted.py` labels keyword-derived URLs as `INVENTED_KEYWORD` and skips them before any HTTP request.
- Only predefined search endpoints and verified trusted links are fetched.

### Medical routing improvements
- Cognitive/neurological symptoms added to all health-indicator lists (`memory loss`, `confusion`, `forgetful`, `dementia`, etc.).
- Medical keyword matching switched from substring to word-boundary matching via `_phrase_in_text()` to prevent `execution` → `cut`, `influence` → `flu`, `operational` → `operation`, `gout` → `go`, and `forgot` → `go` false positives. The same boundary check is now applied to the programming-language guard.
- Common verb forms added (`vomiting`, `coughing`, `sneezing`).
- Additional medical terms added (`side effect`, `side effects`, `statin`, `statins`).
- Additional legal terms added (`self-defense`, `self defense`).
- `gate_explicit_capability_restriction` in `policy_router.py` forces `LOCAL` for short messages whose primary content is a capability restriction ("Do not store this message").

## 8. New validation and safety boundaries

| Boundary | Where enforced |
|----------|----------------|
| Explicit no-network → no external routes | `request_pipeline.process()` |
| Explicit no-tools → no tool routes | `request_pipeline.process()` |

| Invented keyword URLs rejected | `unverified_context_trusted.py` + `validate_fetch_url()` |

| Cognitive symptoms route to trusted evidence | `policy.py` + `policy_router.gate_medical_vet` |

## 11. Remaining model-specific differences

- Wording, length, ordering of minor points, and confidence phrasing differ between Gemma and Llama — this is intentional and allowed.
- Gemma occasionally returns an empty response on first call and needs one retry (observed in harness). This is an Ollama/load issue, not a routing issue.

## 12. Unresolved risks

- The medical keyword list is still keyword-based; novel adversarial phrasings may still bypass or false-positive. The new constraints layer provides a deterministic fallback for explicit denials.
- `PlannerValidator` is not yet wired into a live LLM planner because the current planner is deterministic; any future LLM planner must call it before network execution.
- MedlinePlus search endpoint currently returns HTTP 404 in this environment; the code falls through to DailyMed, but the 404 traffic is still logged.
- Session-memory summarisation occasionally times out (unrelated to routing).
