## 4. Rollback Instructions

To fully disable the new v11 pipeline/escalation features and restore pre-expansion behaviour:

1. Edit `config/capability_flags.yaml`:

   ```yaml
   source_attribution: false
   suggest_web_escalation: false
   auto_web_general_knowledge: false
   trusted_sources_only_critical: false
   ```

2. Alternatively, set environment variables before starting Local Lucy:

   ```bash
   export LUCY_SOURCE_ATTRIBUTION=0
   export LUCY_SUGGEST_WEB_ESCALATION=0
   export LUCY_AUTO_WEB_GENERAL_KNOWLEDGE=0
   export LUCY_TRUSTED_SOURCES_ONLY_CRITICAL=0
   ```

3. Restart Local Lucy (`START_LUCY.sh` or the relevant launcher).

The pipeline/planner/escalation packages remain in the codebase but are functionally inactive when all flags are off and `trusted_sources_only_critical` is disabled.

## 8. Known Residual Risk / Notes

- The `escalation/fetcher.py` DuckDuckGo HTML parser depends on DuckDuckGo's markup; changes to their page structure could break `auto_web_general_knowledge`. The fetcher degrades gracefully to an empty result.
- `auto_web_general_knowledge` never replaces the local answer; it only appends an untrusted-source suggestion.
- Critical-source policy defaults to `trusted_sources_only_critical: true`. Disabling it allows critical categories to use the same routes as non-critical queries.
- HMI rendering of `source_attribution`, `trust_label`, and `escalation_suggestion` fields is out of scope for this branch; the fields are available in `RouterOutcome` for the HMI layer to consume.
- Live model testing was not part of the fast suite; run manual smoke queries after merging to `main`.
- Baseline reuse note: Test results from this session are reusable unless `pipeline/`, `planner/`, `escalation/`, `request_pipeline.py`, `plan_to_pipeline_cli.py`, `request_types.py`, or `capability_flags.yaml` change.
